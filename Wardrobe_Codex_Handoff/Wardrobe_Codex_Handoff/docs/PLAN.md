## 이번 버전의 결정

메인은 추천 카드가 아니라 내 옷 전체 목록이다. 첨부 참고 화면처럼 배경 제거된 옷 사진을 밀도 있게 배치한다. 하단 메뉴는 옷장, AI 코디, 코디북, 마이의 네 개로 통일한다. 옷 추가는 별도 플러스 버튼이다.

초기 기반은 무료 정적 웹 호스팅과 Supabase Free다. 옷 인식·배경 제거·기본 추천은 운영자가 관리하는 로컬 AI 작업기로 처리하는 방안을 우선 검증한다. 유료 API 5,000장 및 재시도 비용을 기본 예산에서 제외한다.

내 옷을 조합하는 것과 내 사진에 실제처럼 입히는 것은 다르다. 기본 코디는 저장된 옷 이미지로 즉시 구성한다. 포즈에 맞춘 가상 착용은 사용자가 요청할 때만 실행하는 실험 기능이며, 상업 이용 가능한 모델과 품질을 검증한 뒤 공개한다.

## 완성 기준

사용자는 옷 등록 후 보관 위치를 확인하고, 한 벌을 고정해 추천받으며, 코디를 저장하고 착용 기록을 남길 수 있어야 한다. 다른 기기에서 같은 계정으로 로그인하면 같은 내용이 나타나야 한다. 운영자는 유입·전환·오류·AI 대기열·무료 한도를 확인할 수 있어야 한다.

## 1 호스팅과 서버 선택

일반 호스팅은 상품명이 아니라 범주다. 정적 웹 호스팅은 화면 파일을 배포하고, Supabase와 Firebase는 로그인·데이터·파일 등 백엔드 서비스를 제공한다. 서로 완전히 대체 관계가 아니며 함께 사용할 수 있다.

| 기준 | 일반 웹호스팅 또는 VPS | Supabase | Firebase |
| --- | --- | --- | --- |
| 기본 역할 | 화면 또는 직접 구축한 서버 | PostgreSQL·인증·파일·실시간 | Firestore·인증·파일·호스팅 등 |
| 장점 | 구성 자유, 기존 서버 활용 | SQL 통계와 관계 데이터에 유리 | 모바일 SDK와 오프라인 기능 |
| 단점 | 보안·백업·서버 관리 직접 수행 | 오프라인 충돌 처리를 직접 설계 | 조회량 과금과 관계 집계 설계 |
| 무료 시작 | 정적 호스팅은 가능, 업체별 조건 | Free 가능, 사진·전송량 제한 | Spark 가능, Storage는 Blaze 필요 |
| 이번 기획 | 무료 정적 화면 배포에 사용 | 중앙 백엔드로 우선 선택 | 필요시 분석·충돌 보고만 별도 검토 |

## Supabase 무료 한도와 용량 설계

공식 Free 기준 DB 500MB, 파일 1GB, 일반 egress 5GB 및 cached egress 5GB, 월 활성 사용자 5만 명, 실시간 동시 연결 200개, 월 메시지 200만 개다. 비활성 1주 후 일시 정지될 수 있고 자동 백업이 포함되지 않는다. 이 숫자가 5만 명의 사진 앱을 무료로 운영할 수 있다는 뜻은 아니다. [1]

원본·누끼·썸네일을 합쳐 옷 한 벌당 평균 500KB로 가정하면 50명 × 40벌은 약 1GB다. 사용자 프로필과 생성 결과를 넣으면 여유가 줄어든다. 베타는 20~30명부터 시작하고 70%·85%·95% 용량 경보를 둔다. 이미지 압축과 썸네일을 사용하되 가상 착용용 원본 품질은 별도로 검증한다.

## Firebase를 선택할 경우

Firestore Standard 무료 범위는 저장 1GiB, 일 읽기 5만·쓰기 2만이다. Firebase Hosting은 저장 10GB와 일 전송 360MB 무료 범위가 있으나 사용자 의류 사진 저장소와 혼동하지 않는다. Cloud Storage는 2026년 2월 3일부터 Blaze 결제 계정 연결이 필요하다. 무료 사용량 안에서 청구액 0원이 가능해도 결제 없는 Spark만으로 사진 저장까지 해결하는 구조는 아니다. [2][3]

## 생성 재시도의 정확한 의미

첫 실행은 선택한 내 옷을 사람 사진에 맞춰 새 착용 이미지로 만드는 것이다. 재시도는 손·무늬·옷 경계·얼굴이 잘못 나오거나 작업이 실패해 다시 실행하는 경우다. 기존에 저장된 결과를 다시 보는 것은 재시도가 아니다. 포즈나 옷 조합 변경은 새 요청으로 기록한다.

## 로컬 실행 위치

설치형 AI는 우선 운영자의 GPU PC에서 실행한다. iPhone과 Android에 큰 모델을 각각 설치하는 방식은 1차 범위에서 제외한다. PC가 꺼지면 신규 AI 처리는 대기하지만 이미 저장된 옷과 규칙 기반 코디는 이용 가능하게 한다. 무료 소프트웨어여도 전기·장비·운영 시간은 발생한다.

GPU를 동시에 여러 작업이 점유하지 않도록 한 작업씩 시작하고 처리 시간·메모리를 측정한다. 의류·사진·모델 버전·설정의 해시가 같으면 저장 결과를 재사용한다. 실패 재시도는 최대 횟수를 제한하고 유료 API로 자동 전환하지 않는다.

## 메인 화면 배치

상단에는 내 옷장 제목, 옷 개수, 검색, 보기 밀도 버튼을 둔다. 그 아래는 보관 위치 칩, 계절 필터, 종류 탭 순서다. 기본 4열, 선택 가능한 3열·5열을 제공한다. PC는 창 폭에 따라 열 수를 늘리고 우측에 선택한 옷과 코디 패널을 둔다.

옷 사진은 배경을 제거하고 같은 시각적 크기로 보정한다. 긴 이름·가격·착용 횟수를 모든 타일에 반복하지 않는다. 선택하거나 상세를 열었을 때 보여준다. 실제 색과 로고는 임의로 바꾸지 않는다. 세탁 중·대여 중·처리 중은 작은 배지로 표시한다.

하단에는 내 옷으로 코디 받기 버튼과 플러스 버튼을 둔다. 버튼은 안전 영역을 확보하고 목록 마지막 옷을 가리지 않는다. 날씨는 상단 한 줄로 요약하며 큰 홍보 말풍선으로 의류를 가리지 않는다.

## 메인 상태와 예외

옷이 없으면 사진 3장으로 시작 안내와 촬영·앨범 버튼을 보여준다. 인식 처리 중에도 원본 썸네일은 표시한다. 필터 결과가 없으면 필터 초기화를 제공한다. 네트워크가 끊기면 저장된 목록과 마지막 동기화 시각을 보여준다. 업로드 실패는 해당 타일에만 표시하고 재전송할 수 있게 한다.

## 한 벌 고정 동작

옷 한 벌을 탭하면 상세 패널과 이 옷으로 코디 버튼이 열린다. 바지 또는 상의를 고정하면 해당 품목은 교체에서 제외한다. 기본 추천은 내 소유이며 지금 이용 가능한 옷만 포함한다. 구매 고민 품목과 다른 사람 소유 품목은 명시적으로 선택하기 전까지 제외한다.

## 5 옷 등록과 추천 규칙

## 등록 입력값

필수는 사진, 종류, 소유 구분이다. 보관 위치는 기본 위치를 자동 선택하되 미지정으로 저장할 수 있다. 색상·계절은 AI가 제안하고 사용자가 수정한다. 구매가·브랜드·소재·사이즈·URL·메모는 선택 입력이다. 가격 미입력 항목을 0원 상품으로 해석하지 않는다.

보관 위치는 위치 테이블을 참조한다. 안방 옷장 이름을 바꾸면 그곳에 있는 모든 옷에 새 이름이 적용된다. 위치를 삭제할 때는 다른 위치로 이동 또는 미지정을 선택하고 옷을 함께 삭제하지 않는다.

## 추천 순서

1 소유·공유 허용·현재 상태를 확인한다. 2 기온·비·행사에 맞는 후보를 거른다. 3 고정 아이템과 색상·스타일·레이어링을 맞춘다. 4 사용자가 좋아한 조합과 최근 착용 이력을 반영한다. 5 비슷한 결과가 반복되지 않도록 3개 후보를 고른다.

AI가 새로운 상품명을 상상하더라도 결과에 존재하지 않는 item_id를 넣을 수 없게 서버에서 검증한다. 신발·가방·시계·목걸이·머리띠는 선택 가능한 추가 구성으로 두고, 소유하지 않은 액세서리를 필수처럼 요구하지 않는다.

## 기록과 비교

오늘 입기는 실제 착용 확인이다. 단순 코디 열람이나 달력 예약은 횟수에 포함하지 않는다. 같은 날 같은 기록의 중복 탭은 한 번만 저장한다. 취소하면 집계에서도 빠진다. 날짜는 사용자 시간대 기준으로 저장·표시한다.

비포는 사용자 저장 시점의 코디 스냅샷이고 애프터는 AI가 보완한 새 버전이다. 좌우 드래그로 비교하며 추가 또는 바뀐 옷 목록을 함께 보여준다. 원래 코디를 덮어쓰지 않는다.

## SNS와 사진 가져오기

1차는 공유 시트와 이미지 저장·설명 복사를 제공한다. 공유 화면을 열었다고 실제 게시 완료로 집계하지 않는다. 외부 URL은 지원 쇼핑몰부터 시작하고 차단·품절·이미지 접근 실패 시 직접 사진 등록으로 전환한다. 외부 자료는 이용 권한과 서비스 조건을 확인한다.

## 동기화 규칙

서버 저장 성공 후 다른 기기에 변경 알림을 보낸다. 실시간 알림은 갱신 신호이며 재접속 시 서버의 최신 데이터를 다시 조회한다. 실시간 연결만 믿고 누락된 데이터를 방치하지 않는다. 로그아웃 시 개인 캐시를 지운다.

오프라인 편집은 로컬 대기열에 저장하고 재연결 시 반영한다. 레코드 version으로 동시 수정을 감지한다. 서로 다른 필드는 병합할 수 있지만 같은 보관 위치나 상태가 충돌하면 사용자에게 선택을 요청한다. 삭제는 tombstone으로 전달한 뒤 정리한다.

사진 업로드와 DB 저장은 단계별 상태로 관리한다. 같은 요청 ID는 중복 옷을 만들지 않는다. 실패한 업로드와 참조가 끊긴 파일은 정리 작업을 수행한다. 코디 사진 공개와 개인 옷장 공유 권한은 별개다.

## 보안과 로컬 작업기

모든 개인 테이블에 사용자별 RLS를 적용하고 이미지 버킷은 비공개로 둔다. 공유할 때만 범위가 제한된 접근을 제공한다. 서비스 비밀키는 앱·웹·확장에 넣지 않는다. 로컬 작업기는 인증된 작업만 가져오며 임시 사진을 완료 후 삭제한다. GPU PC의 포트를 인터넷에 그대로 공개하지 않는다.

크롬앱이라는 명칭은 설치 가능한 웹앱과 크롬 확장으로 구분한다. 이번 기획에서는 PC 웹앱과 확장을 구현하며, 별도의 과거 Chrome Apps 패키지를 만들지 않는다.

## GitHub를 기준으로 개발

실제 코드는 GitHub 저장소에서 버전 관리한다. 터미널형 코딩 에이전트는 프로젝트 파일 수정·실행·테스트·Git 작업에 사용한다. ChatGPT 대화는 기획·기능 판단·디자인 검토에 사용한다. Word는 기획 문서 편집용이며, Work를 뜻한다면 시안과 작업 결과 검토 공간으로 활용한다.

설치형 GPT라는 표현은 데스크톱 코딩 도구와 로컬 모델 실행기를 구분해야 한다. 전자는 개발 도구이고 후자는 서비스의 AI 처리 엔진 후보다. 창이 설치형이라고 해서 모델이 무료 또는 오프라인으로 실행되는 것은 아니다.

권장 저장소 구분은 apps/mobile, apps/web, apps/extension, packages/domain, packages/api, supabase/migrations, services/ai-worker, docs다. 공통 타입·검증·추천 규칙은 공유하고 화면 코드는 억지로 모두 같게 만들지 않는다.

기능별 브랜치와 PR로 변경을 검토하고, main은 동작하는 상태를 유지한다. 비밀키·원본 사용자 사진은 Git에 올리지 않는다. .env.example에는 변수 이름만 기록한다. 데이터베이스 변경도 migration으로 관리한다. 외부 배포와 스토어 등록은 별도 검증 단계로 진행한다.

## 원시 이벤트 명세

app_open, sign_up_completed, item_upload_started, item_created, background_remove_completed, outfit_requested, outfit_saved, wear_confirmed, share_opened, tryon_requested, tryon_completed, sync_failed를 정의한다. event_id로 중복 제거하고 서버 확인 가능한 성공 이벤트는 서버에서 확정한다.

기본 필드는 event_id, event_name, occurred_at, received_at, anonymous_id, user_id, session_id, platform, app_version, source, medium, campaign, properties다. 로그에 얼굴 사진·비밀번호·인증 토큰·전체 개인 메모를 넣지 않는다.

분석 원시 이벤트 보관은 초기 30일을 제안하고 일별 집계는 장기 보관한다. 모든 클릭과 마우스 이동을 수집하지 않는다. 작은 프로젝트의 DB 500MB를 로그가 소진하지 않도록 일별 적재량을 표시하고 삭제·집계 작업을 예약한다.

## 웹과 캠페인 링크

홍보 링크마다 utm_source, utm_medium, utm_campaign, utm_content를 붙인다. 예를 들어 Instagram 소개 링크와 릴스 링크를 구분한다. 최초 유입과 최근 비직접 유입을 따로 저장하며 직접 방문으로 이전 출처를 덮어쓰지 않는다. referrer가 없거나 측정이 차단되면 알 수 없음으로 남긴다.

## 앱 설치와 기기 전환의 한계

웹에서 스토어로 이동한 뒤 앱을 설치하면 UTM이 자동으로 그대로 이어지지 않는다. Android 설치 리퍼러와 스토어별 캠페인 분석 등 지원 수단을 검토하고, iOS의 개인별 유입 추적은 개인정보 보호 및 플랫폼 제약을 반영한다. 정확히 모르는 설치 출처를 추정해 확정값으로 표시하지 않는다.

같은 계정으로 로그인한 이후의 기기별 행동은 계정 기준으로 연결할 수 있다. 로그인 이전에는 브라우저·기기별로 서로 다른 사람처럼 집계될 수 있다. 추천 코드와 가입 계기 선택 설문을 보조 수단으로 두되 추적 데이터와 자기 응답을 별도 표시한다.

## 관리자 화면 구성

상단 네 개 카드에는 활성 사용자, 신규 가입, 첫 코디 완료율, AI 실패율을 표시한다. 가운데에는 일별 방문·가입 추이와 전환 단계를 둔다. 아래에는 유입 채널별 방문·가입·옷 등록·코디 저장 표와 캠페인별 성과를 둔다. 우측 상태 영역에는 로컬 작업기 연결·대기열·저장 용량 경보를 둔다.

채널 성과에는 방문자 수와 전환율을 함께 표시한다. 적은 표본의 높은 전환율만 보고 성공으로 표시하지 않는다. 기간을 바꾸면 모든 카드·차트·표가 동일 기준으로 바뀐다. CSV 내보내기는 관리자만 가능하고 가명 통계를 기본으로 한다.

## 무료 모니터링 운영

유료 분석 도구를 필수로 도입하지 않는다. 자체 이벤트·집계·관리자 페이지로 시작하고 오류 로그와 AI 작업 상태를 함께 본다. 서버 로그와 제품 통계는 별개로 관리한다. 이메일 전송은 기존 계정 또는 무료 SMTP 범위를 활용하며, Supabase 기본 SMTP를 일반 고객용 메일 발송 수단으로 가정하지 않는다. [7]

## 전력과 용량 계산 예시

예산 예시로 추가 소비 전력 0.25kW를 하루 8시간, 30일 사용하면 60kWh다. 단가를 임의로 200원/kWh로 놓으면 12,000원이지만 실제 전기요금은 계약·누진·기존 사용량에 따라 달라진다. 청구액으로 단정하지 않는다.

원본·누끼·썸네일 합산 500KB 가정에서 100명 × 50벌은 약 2.5GB로 Supabase 무료 파일 한도를 넘는다. 캐시와 썸네일로 전송량을 줄여도 저장 공간 자체가 늘어나는 문제는 해결되지 않는다. 무료 베타와 공개 서비스의 규모를 구분한다.

저장 공간 85% 도달, 대기열 지속 증가, 복구·가용성 요구 상승을 전환 검토 신호로 삼는다. 사용자 수만으로 결정하지 않는다. Pro 기본 요금은 현재 월 $25부터이며 실제 사용량과 구성을 다시 확인한다. 비용 상한 알림과 사용자별 등록·생성 한도를 함께 둔다. [1]

개발 기간은 인력과 숙련도·AI 품질에 좌우된다. 1차 계획은 약 10~16주를 가정하되 확장·로컬 AI·동기화의 검증 결과에 따라 조정한다. 자동 생성된 코드만으로 출시 준비가 완료되었다고 판단하지 않는다.

## 플랫폼별 등록 준비

iOS는 서명·배포 빌드, TestFlight, 스크린샷, 개인정보 항목, 계정 삭제, 필요 로그인 정책과 결제 복원을 확인한다. Android는 서명 AAB, 데이터 보안 양식, 테스트 트랙, 권한·뒤로 가기·사진 접근을 점검한다. 신규 개인 계정의 12명 14일 연속 테스트 요건을 일정에 포함한다. [12][13]

웹은 HTTPS·도메인·비밀번호 복구·캐시 갱신을 검증한다. 크롬 확장은 이미지/페이지 접근 권한을 최소화하고 사용자 동작 시에만 저장한다. 개인정보처리방침과 목적에 맞는 권한 설명을 준비한다. 스토어 심사 통과와 처리 기간을 보장하지 않는다.

## 출시 차단 조건

다른 계정의 옷 사진 접근, 삭제한 데이터의 재등장, 중복 착용 집계, 없는 옷 추천, 원인 모를 유료 API 호출, AI 작업 무한 재시도는 출시 전에 해결한다. 서버 중단·PC 종료·업로드 실패에서도 사용자가 상태를 이해하고 다시 시도할 수 있어야 한다.

## 12 후속 기능과 검증 목록

## 2차 확장

가족 공유와 대여 승인·반납, URL 가져오기, 손민수 코디, 퍼스널 컬러 참고 제안, 메이크업·금속색 비교, AI 친구, 관련 세탁 팁·소재 사전을 추가한다. 실시간 접속자와 영상 워킹보다 일상 사용 빈도가 높은 기능을 먼저 검증한다.

## 3차 확장

공개 코디·팔로우·댓글·지역 커뮤니티·제휴 구매·스타일리스트 티어·중고 제안·수선 제안을 검토한다. 커뮤니티는 신고·차단·운영 대응을 함께 구축한다. 제휴 구매는 판매액과 수수료를 구분하고 취소·반품 후 정산한다. AI 친구는 자체 제작 또는 이용 권한이 확보된 캐릭터로 제공한다.

## 화면 디자인 적용 기준

첨부된 참고 이미지의 장점은 작게 정리된 의류 사진으로 소유한 옷을 빠르게 훑는 것이다. 최종 홈 시안은 이를 반영한 4열 그리드와 간결한 필터다. 앞서 제작된 오늘 추천 중심 화면이 있다면 최종 홈이 아니라 AI 코디 탭의 참고안으로 사용한다. PC 시안도 첫 진입을 옷장으로 맞춘다.

## 개발 검증 체크리스트

□ 동일 계정의 네 플랫폼에서 같은 옷과 위치가 보인다.

□ 한 벌을 고정하면 추천을 다시 받아도 고정 옷이 유지된다.

□ 세탁·대여 중인 옷과 구매 고민 상품은 기본 추천에서 제외된다.

□ AI 작업기가 꺼져도 기존 옷 조회와 기본 조합이 작동한다.

□ 동일 사진·설정의 작업 결과가 캐시로 재사용된다.

□ 공유 시트 열기와 실제 게시 완료를 통계에서 혼동하지 않는다.

□ UTM 없는 유입을 임의로 Instagram 또는 검색으로 배정하지 않는다.

□ 용량·트래픽·로그 증가를 관리자에서 볼 수 있다.

□ 계정 삭제 시 사진·공유·캐시·대기 작업의 삭제 범위를 확인한다.
