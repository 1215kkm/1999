# 개발 순서와 완료 기준

## 1. 로컬 웹 프로토타입
기존 저장소 확인 → 반응형 화면 → 테스트 데이터/로컬 저장 → 옷 추가·조회·수정·삭제 → 위치와 필터 → 한 벌 고정 조합 → 코디북.
- 360px 모바일부터 PC까지 목록과 버튼이 잘리지 않는다.
- 새로고침 후 로컬 데이터가 남고 테스트 데이터 초기화가 가능하다.
- 등록한 옷이 필터/위치와 상세 화면에 동일하게 나타난다.
- 사진 파일은 적절한 로컬 저장소를 사용하고 내보내기/삭제 동작을 고려한다.
- 고정한 옷은 후보 재추천 시 유지된다. 실제 존재하는 이용 가능한 옷만 조합한다.
- 액세서리가 없으면 존재하지 않는 아이템을 만들어 추천하지 않는다.

## 2. Supabase 연동
마이그레이션 → 인증 → private Storage/RLS → 데이터 접근 계층 교체 → 이미지 업로드 실패 복구 → 삭제/계정 삭제.
- 서로 다른 두 테스트 계정이 상대 옷/사진/코디에 접근할 수 없는지 검증한다.
- service role은 서버/worker 전용. 화면에서 관리자 여부만 숨기는 방식 금지.
- 파일 업로드와 DB 저장 사이의 중간 실패 및 고아 파일을 처리한다.

## 3. 로컬 AI
인식/배경 제거는 별도 worker로 큐 처리. 앱 응답은 비동기 상태로 표시.
- 모델별 라이선스 URL/확인일/VRAM/속도/품질을 기록한다.
- worker가 꺼져도 기존 옷 보기와 규칙 추천은 작동한다.
- 결과 캐시 키는 원본 해시+모델 버전+설정. 실패 횟수 제한, 취소, 타임아웃.
- 가상 착용은 검증 후 옵션으로만 추가. 유료 fallback 없음.

## 4. 모바일과 확장
공통 타입/추천 규칙/API 계약 공유, 화면은 플랫폼에 맞게 작성.
- iOS/Android 실제 기기에서 사진 접근, 로그인 복귀, 안전 영역, 키보드, 공유 확인.
- Chrome 확장: 사용자가 선택한 이미지/URL을 등록하며 최소 권한 사용.
- 외부 URL 서버 다운로드는 사설 IP/리다이렉트/크기/타입 제한으로 SSRF를 방지한다.
- 외부에서 가져온 아이템은 '구매 고민'으로 별도 표시, 소유 옷 추천에서 제외.

## 5. 동기화와 통계
서버 저장 성공 → 다른 기기 갱신. 재접속 시 최신 데이터 재조회.
오프라인 큐, 요청 중복 방지, version 충돌 감지, 삭제 tombstone을 설계한다. 충돌을 조용히 덮어쓰지 않는다.
관리자 샘플 모드와 운영 수치 모드를 명확히 구분한다.

## 6. 출시
무료 한도 경보, 데이터 삭제/백업 정책, 개인정보 문서, 접근성, 오류 추적 → 비공개 베타 → 스토어 빌드/심사 자료 → 단계적 공개.
등록료/테스트/심사/로그인 규칙은 제출 시 최신 공식 문서로 확인한다. 구현 완료와 스토어 승인 완료를 구분한다.

## 매 작업 종료 기록
PROGRESS.md에 변경 파일, 실행 명령, 테스트 결과, 미연결 부분, 남은 결정, 다음 작업을 기록한다. 검증하지 않은 항목을 통과로 쓰지 않는다.
